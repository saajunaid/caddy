# Developing Caddy locally with Claude Code

Everything runs on your workstation: the app, a private copy of the database, and Claude Code.
Production (Vercel + Supabase) is only touched by merging to `main`, exactly as in the cloud.

## 1. Install once

| Tool | Why | Check |
|---|---|---|
| Git | the code | `git --version` |
| Node.js 22 | runs the app | `node -v` → v22.x |
| pnpm 10 | packages | `corepack enable` then `pnpm -v` |
| Docker Desktop | local database (Supabase) | `docker ps` works |
| GitHub CLI | pull requests from the terminal | `gh auth login` |
| Claude Code CLI | your coding agent | `claude --version` |

## 2. Get the code

```sh
git clone https://github.com/saajunaid/caddy.git
cd caddy
corepack enable
pnpm install
```

## 3. Start a local database (a private copy of Supabase)

```sh
pnpm exec supabase start
```

The first run downloads Docker images (a few minutes). It applies every migration in
`supabase/migrations`, so the local database has the same tables and security rules as production,
but none of your real data. Useful local addresses:

- Database UI (Studio): http://localhost:54323
- Emails (sign-in codes land here, nothing is really sent): http://localhost:54324

Stop it with `pnpm exec supabase stop` (your local data is kept).

## 4. Point the app at the local database

```sh
pnpm exec supabase status -o env
```

Copy three values from that output into a new `.env.local` file in the project folder:

```sh
NEXT_PUBLIC_SUPABASE_URL=<API_URL>
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<PUBLISHABLE_KEY>
SUPABASE_SECRET_KEY=<SECRET_KEY>
APP_TIMEZONE=Europe/Dublin
```

These are local-only keys. **Never put production keys in `.env.local`.**

Optional, to try push notifications locally: run `pnpm dlx web-push generate-vapid-keys` and add
`NEXT_PUBLIC_VAPID_PUBLIC_KEY=` and `VAPID_PRIVATE_KEY=` lines.

## 5. Create your local login

Sign-ups are switched off, so create the household and your account with the same script the
GitHub Action uses (use any email; the code arrives in the local mailbox above):

```sh
SUPABASE_URL=http://127.0.0.1:54321 SUPABASE_SECRET_KEY=<SECRET_KEY> \
MEMBER_EMAIL=you@example.test MEMBER_NAME="Your Name" \
node --experimental-strip-types scripts/add-household-member.ts
```

## 6. Run the app

```sh
pnpm dev
```

Open http://localhost:3000, sign in with the email above, and read the code at
http://localhost:54324.

To fill Housing with real listings locally (about 4 minutes, reads newstarterhomes.ie politely):

```sh
SUPABASE_URL=http://127.0.0.1:54321 SUPABASE_SECRET_KEY=<SECRET_KEY> APP_URL=http://localhost:3000 \
node --experimental-strip-types scripts/jobs/run.ts job housing-daily
```

## 7. Work with Claude Code

```sh
cd caddy
claude
```

Claude reads `CLAUDE.md` (project rules) and `docs/PLAN.md` automatically. A good first message:
"Read docs/PLAN.md and docs/LOCAL_DEV.md, then build app-wide search as one small PR."

The workflow is the same as in the cloud:

1. Work on a branch: `git switch -c feature/search`.
2. Before pushing, run the checks: `pnpm check` (lint, typecheck, unit tests, format) and
   `pnpm build`. For database changes also run the DB tests:
   ```sh
   pnpm db:local   # a throwaway Postgres on port 54329, separate from Supabase
   DATABASE_URL=postgres://postgres:postgres@localhost:54329/postgres pnpm test:db
   ```
3. Push and open a pull request: `git push -u origin feature/search` then `gh pr create --fill`.
4. GitHub runs CI and Vercel builds a preview link. Merge when green: `gh pr merge --merge`.
5. Merging to `main` deploys the app to Vercel and applies any new database migration to
   production automatically (GitHub Action "Apply database migrations").

## Things that keep running without you

- **Daily jobs** (housing check, utilities, family reminders, exchange rates, nearby places) and
  the **weekly** job run on GitHub Actions. They're free and don't depend on Claude.
- **Housing news** is a Claude Code routine that runs in the cloud each morning at 06:47. It uses
  your Claude plan's usage. To run it yourself instead, see `research/README.md`. Any agent, such
  as `claude -p`, Gemini CLI or a local model, can write the JSON and send it with
  `scripts/research/ingest.ts` and the `RESEARCH_INGEST_TOKEN`.

## Troubleshooting

- `docker` errors: start Docker Desktop first.
- Port in use: `pnpm exec supabase stop`, or change ports in `supabase/config.toml`.
- Sign-in code never arrives: open http://localhost:54324. Codes never leave your machine locally.
- Types out of date after a migration: `pnpm exec supabase gen types typescript --local --schema public > src/lib/supabase/database.types.ts`
  then add the "Generated by" line at the top and run `pnpm exec prettier --write` on it (or use
  `pnpm db:types`).
